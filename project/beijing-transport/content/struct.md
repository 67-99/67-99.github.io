## 项目结构
为了连接以上功能，整个项目框架如下：
```
├── resource/
│   ├── baseline/   ←这个是线路基线与站位
│   ├── track/      ←这个是具体配线图与站台
│   ├── timetable/  ←这个是时刻表
│   ├── train/      ←这个是列车数据
│   └── 其他中间脚本与数据
├── index.html
├── script.js
├── debug.js
└── styles.css
```

### 线路基线
线路基线baseline是显示基础线网的多段折线，里面按照线路实际层级进行模糊分段，使得线网重叠显示与实际一致。由于高德地图使用GCJ-02坐标系，所以我对整个基线有所调整，并根据实际位置有相应调整。这个baseline同时承载了显示基础线网与配线图基线的作用，是显示的根基。

本项目的线路id命名规则遵从北京地铁数字命名法（贯通或分段用NSEW方位表示）+部分首字母缩写，其中只有机场线、西郊线是首字母缩写（CAE、DAE、XJ，T1为亦庄T1线）
> 目前北京地铁线路对应id有：M1, M1E, M2, M3, M4, M4S, M5, M6, M7, M8, M9, M10, M11, M12, M13, M14, M15, M16, M17, M18, M19, M24,M25, M25W, M26, M27, XJ, CAE, DAE, T1

### 配线图
配线图是由上文[北京地图配线图](https://sierraqin.github.io/metro)中的配线转换而来的。我以baseline为基线，编写了每个站上下行的偏移情况和站台配置`tracks.json`，格式如下：
```json
[
    线路id: {
        "main": [
            [
                {"n": 站名, "offset": [in, st, out]},
                {"sl": [lat, lng], "offset": offset}
                ...
            ],
            [
                ...
            ]
        ],
        "stations":[
            {
                "n": 站名,
                "sl": [lat, lng],
                "pos": [[start, len], ...]
            },
            ...
        ]
    }
]
```
其中，`main`字段里存储上下行，上下行位置约束由`offset`字段完成。offset的单位UNIT为0.0001°，即约11.132米，所有偏移均相对上行方向。偏移值由正半轴、0与负半轴组成：正半轴为上行方向右侧，0为baseline基线位置，负半轴为上行左侧方向。

对于站点（含参数`"n"`）而言，可以设置它的站前、站台、站后的轨道偏移值。当参数不及3个时，会根据最后一位自动补全至3位。对于控制点（含参数`"sl"`）而言，可以设置在此点的偏移值。配线图线条控制点（含站点控制点）要求中间节点的两侧节点至少有一个节点的偏移值与其相同，否则转换程序会报错拦截（朴实无华的拦截方式(>ε·)ﾉ

站台中默认有`"sl"`字段表示站点位置，`"pos"`表示多个站台位置，格式为`[起始偏移, 长度]`，若无长度默认长度为1。

以下为常用offset：
|站台类型|上下行offset|站点pos|
|:--:|:--:|:--:|
|地下岛式站台|`[2]`<br>`[-2]`|`[[-1, 2]]`|
|地上岛式站台|`[1, 2, 1]`<br>`[-1, -2, -1]`|`[[-1, 2]]`|
|侧式站台|`[1]`<br>`[-1]`|`[[-2], [2]]`|

### 时刻表
北京地铁有官方时刻表图片，但分布在不同的运营商中，分别为[北京地铁](https://www.bjsubway.com/station/)、[京港地铁](https://www.mtr.bj.cn/service/line/line-4)、[京投运营](https://www.bjmoa.cn/trainTimeList_363.html)和北京公交，其中北京公交我没找到时刻表，所以T1线没有录入。获取到时刻表图片后使用AI识图转换为具体时刻，但转换为纯时刻时由于数据量大，很容易注意力自激。经过多次测试后以下提示词准确率较高，且不会注意力自激：
```text
将这个生成json，分上下行、weekday和weekend，存储对应分钟（如8:00对应480），只给出图片几站；若有时间隔天，0与1440各存一个（如0:05存5与1445）参考：
{
  "up": "安河桥北",
  "down": "天宫院",
  "stations": [
    {
      "station_name": "东大桥",<=注意这里不要自己加“站”字，与图片保持一致
      "up": {
        "weekday":
          {
            "5": [
……
```
为了反推车次，我在这基础上添加了小交路终点与越行扣车站点，格式如下：
```json
"short_end": {
    "up": ["潞城", "草房", "通州北关"],
    "down": ["朝阳门", "车公庄西", "海淀五路居"]
},
"pause": {
    "up": ["通运门", "常营"],
    "down": ["通运门", "常营"]
},
```
尽管如此，仍有大量时刻错误，所以vibe了一个简易检测程序`timetable_check.py`，目前正在对时刻表进行排查。
